## 引言

市场上对「谁能做 AI 落地」的判断长期依赖两类不可核验的信号：技术栈清单与工作年限。前者把工具熟练度当成交付能力，后者把时间当成长度。结果是招聘方只能凭面试印象定价，从业者也无法判断自己卡在哪一层。

本文件把判断依据换成一个可核验的问题：**这个人对什么负责**。责任对象变了，级别才变；技术栈变多、证书变多，都不构成升级理由。为了让「负责」可验证，每一级都绑定可提交的证据材料，并规定评价程序与复评周期。

本文件的编写遵循三条取舍：只规定可核验的内容；不预设任何单一技术路线；不把企业内部分级包装成行业标准。与外部体系的关系见第 5.3 条。

## 1 范围

本文件规定了前沿部署工程师（Forward Deployed Engineer，以下简称 FDE）的术语和定义、能力等级划分、各等级的能力要求与证据要求、能力域与档位对应关系、评价方法与评价程序。

本文件适用于：

a) 企业内部对从事 AI 场景落地岗位人员的能力评价、定级与晋升评审；

b) 企业对外发布该岗位招聘信息时的岗位分级与任职要求描述；

c) 从业者对自身能力水平的自评与证据准备。

本文件不适用于：

a) 职业技能等级认定、职业资格评价等需要行政资质的活动；

b) 作为薪酬承诺、就业承诺或任何一方的报价依据；

c) 对个人能力的唯一结论性判断（见 9.6 复核与申诉）。

## 3 术语和定义

GB/T 20000.1 界定的以及下列术语和定义适用于本文件。

### 3.1

**前沿部署工程师　forward deployed engineer（FDE）**

进入客户业务现场，以可度量的业务场景为单位，完成从问题诊断、方案实现、评估验收到交付接管全流程的工程角色。

注：该角色与「算法工程师」「实施顾问」的区别在于同时对业务结果与工程实现负责，并以可复用资产作为交付的副产品。

### 3.2

**责任半径　scope of responsibility**

评价级别的唯一判据，由责任对象、失败后果与不可替代性三个因素合成。

注：责任对象指「对什么负责」，按任务 → 场景 → 项目群 → 组织体系 → 行业方法递进；失败后果指该级失手时损失的量级；不可替代性指该级工作的可替代程度。

### 3.3

**能力档位　capability mark**

描述某一能力域掌握程度的五级刻度，依次为依循、独立、应变、系统、行业。

注：五个档位与五个级别一一对应，对应关系见 5.2。

### 3.4

**台阶　step-up**

某一等级相对上一等级在责任范围上发生的实质变化。

注：台阶必须是可观察的具体变化，不得使用形容词表述；判定要点见附录 A。

### 3.5

**能力域　capability domain**

用于分解 FDE 能力的五个观察维度，即业务认知、场景工程、AI 技术与调试、交付保障、交付工程化。

### 3.6

**证据卡　evidence pack**

按能力域划分的六类可提交材料，用于支撑等级判定，即业务诊断、场景与验收、数据与权限、AI 调试与评估、交付运营、资产化。

### 3.7

**资产　asset**

可在第二次交付中直接复用的产出物，包括连接器、模板与评估集三类。

注：判定标准是「第二次交付确实用上了」，而非「文档写完了」。

### 3.8

**双通道　two tracks**

技术交付通道（T）与业务交付通道（B）。两条通道共用同一责任刻度与同一等级序列，仅能力权重不同。

### 3.9

**量化口径　metric language**

某一等级在汇报价值时应使用的度量语言，随等级升高由任务效率逐级上升到经营与行业口径。

### 3.10

**定级评审　levelling review**

依据提交的证据材料与责任范围，由评审人判定等级的正式过程；与自评（3.11）相区别。

### 3.11

**自评　self-assessment**

从业者依据本文件自行判断等级并识别缺口的过程，其结果仅用于定位，不作为定级结论。

## 5 总则

### 5.1 评价原则

**5.1.1 级别由责任半径决定**　评价应以责任对象、失败后果与不可替代性为依据，不以技术栈广度、证书数量或工作年限为依据。

**5.1.2 证据优先于自述**　每一等级均应提交可核验材料（见附录 B）。缺少材料的能力项按「待验证」记录，不得以自述替代。

**5.1.3 双通道共用一把尺子**　技术交付与业务交付两个通道的同一等级，责任半径相同、薪酬区间相同，仅能力权重不同（见 5.4）。

### 5.2 等级与档位对应关系

五个能力档位与五个能力等级一一对应，见表 1。

**表 1　能力档位与等级对应关系**

| 档位 | 含义 | 对应等级 | 核心关键词 |
|---|---|---|---|
| 依循 | 有模板或指引时能完成，不需要自行判断 | L1 | 执行 |
| 独立 | 无指引也能独立完成标准情形 | L2 | 独立 |
| 应变 | 能处理异常与非标准情形，并做出取舍 | L3 | 统筹 |
| 系统 | 能把做法固化为机制或标准，供他人照做 | L4 | 体系 |
| 行业 | 能影响外部：被同行采纳，或参与标准制定 | L5 | 方法 |

三条硬性规则：

a) 相邻两级在同一能力域上不得同档。若同档，该能力域不能区分两级；

b) 不得跳档。升档应在同一能力域上补充该档所要求的证据；

c) 每个能力域在每个等级上均应有具体描述（见 7.3），仅给出档位名称不构成要求。

### 5.4 双通道的能力权重

**表 2　双通道能力权重**

| 能力域 | T 通道权重 | B 通道权重 |
|---|---|---|
| 业务认知 | 3 | 5 |
| 场景工程 | 4 | 5 |
| AI 技术与调试 | 5 | 3 |
| 交付保障 | 3 | 4 |
| 交付工程化 | 5 | 3 |

注：权重用于评价时的侧重判断，不用于计算总分。等级判定按 8.3 执行。

## 6 能力等级与要求

### 6.1 等级划分

能力等级自低到高为 L1 至 L5，各等级的名称、责任对象与岗位名称见表 3。

**表 3　等级总表**

| 等级 | 名称 | 核心关键词 | 档位 | 责任对象 | T 通道岗位 | B 通道岗位 |
|---|---|---|---|---|---|---|
| L1 | 初级 | 执行 | 依循 | 任务 | 初级交付工程师 | 初级业务分析 |
| L2 | 中级 | 独立 | 独立 | 场景 | 交付工程师 | 场景交付顾问 |
| L3 | 高级 | 统筹 | 应变 | 项目群 | 高级交付工程师 | 高级场景顾问 |
| L4 | 资深 | 体系 | 系统 | 组织体系 | 资深交付工程师 | 场景交付负责人 |
| L5 | 专家 | 方法 | 行业 | 行业方法 | 交付专家 | 场景专家 |

注：「专家」为本文件对 L5 的等级名称，属行业通用职级语境，不构成对任何个人或机构的能力评价。

### 6.2 L1（初级／执行／依循）

**表 4　L1 能力要求**

| 项 | 内容 |
|---|---|
| 本级的台阶 | 入门基线：从「会用工具」变成「能交干净一件事」。 |
| 能力档位 | 依循 |
| 责任半径 | 负责：一件边界清晰的任务按时按质交付。不负责：场景范围与验收的定义、预算、客户关系 |
| 典型范围 | 1 个场景中的单个任务；1 个系统内 1—2 个模块；对接一线使用者与导师；时间尺度天到周；不承担预算决策 |
| 能力档位要求 | 业务认知 依循；场景工程 依循；AI 技术与调试 依循；交付保障 依循；交付工程化 依循 |
| 证据要求 | a) 能独立跑通既有模板并说明每步在做什么；b) 有失败样例与修复记录（不应仅提供成功截图）；c) 交接时能说清「哪里最容易出错」 |
| 交付产物 | 可运行的模块或配置、启动说明、失败样例记录 |
| 量化口径 | 任务级耗时与返工次数（分钟／小时口径） |
| 晋升条件 | a) 连续 3 个任务无需返工；b) 能自行判断「该不该暂停并求助」；c) 至少 1 份文档被他人直接复用 |
| 破格条件 | 不适用。本级价值在基本功，跳过等于把风险留给下一级 |
| 常见越级误区 | 把「用过很多工具」当成能力——工具熟练度不等于交付能力 |
| 失败形态 | 任务做完但交不干净：无文档、无失败样例，第二个人接手需从头问起 |

### 6.3 L2（中级／独立／独立）

**表 5　L2 能力要求**

| 项 | 内容 |
|---|---|
| 本级的台阶 | 从「交任务」到「对结果负责」——开始为一条流程的成败签字。 |
| 能力档位 | 独立 |
| 责任半径 | 负责：一个场景从需求确认到上线后运行的全环。不负责：多场景优先级、组织机制、跨部门资源调配 |
| 典型范围 | 1 个场景全环；1—3 个系统的数据与接口打通；对接业务负责人、一线骨干与 IT／数据团队；时间尺度周到月；单场景量级预算（需报批） |
| 能力档位要求 | 业务认知 独立；场景工程 独立；AI 技术与调试 独立；交付保障 独立；交付工程化 依循 |
| 证据要求 | a) 范围卡（场景边界、基线数字、验收动作）；b) 不少于 20 条失败样例集，能说明其失效条件；c) 一次真实流程跑通记录（使用人、时间、动作） |
| 交付产物 | 可运行场景、验收单、失败样例集、运行手册初版 |
| 量化口径 | 场景指标（准确率、处理周期、单次耗时、错误率） |
| 晋升条件 | a) 独立完成不少于 2 个场景，其中 1 个连续运行 4 周以上；b) 能自行定义基线并将验收写成可判断条件；c) 交付物中不少于 1 件被第二个场景复用 |
| 破格条件 | 具备同等规模场景的完整交付证据（含验收与接管）可跨过任务级考察，但不免除证据评审 |
| 常见越级误区 | 把「系统上线」当交付完成——上线只是开始 |
| 失败形态 | 场景做完但无人使用：验收写的是功能，不是业务变化 |

### 6.4 L3（高级／统筹／应变）

**表 6　L3 能力要求**

| 项 | 内容 |
|---|---|
| 本级的台阶 | 从「做好一个」到「决定做哪几个」——第一次拥有取舍权。 |
| 能力档位 | 应变 |
| 责任半径 | 负责：一组场景的组合、优先级与资源，以及使攻坚可重复的机制。不负责：组织级标准与人才培养体系 |
| 典型范围 | 3—10 个场景的组合（含取舍）；跨系统跨部门编排；对接部门负责人及以上与多方供应商；时间尺度季度；参与预算编制 |
| 能力档位要求 | 业务认知 独立；场景工程 应变；AI 技术与调试 应变；交付保障 应变；交付工程化 独立 |
| 证据要求 | a) 场景组合规划（为什么先做这 3 个、放弃那 5 个）；b) 可重复的评审与运营机制（谁在什么节点检查什么）；c) 至少 1 次跨部门冲突的处理记录（含取舍理由） |
| 交付产物 | 组合路线图、评审与运营机制、架构决策记录、可复用资产不少于 2 件 |
| 量化口径 | 组合价值（总成本、总工时、合格率、复用率） |
| 晋升条件 | a) 同时统筹不少于 3 个场景且全部达验收；b) 建立被他人沿用不少于 2 次的机制或资产；c) 资源不足时能做出可解释的取舍 |
| 破格条件 | 在单一复杂系统上达成 L4 级资产化成果（跨项目复用不少于 3 次）可破格，需评审一致通过 |
| 常见越级误区 | 把「协调会议多」当统筹能力——统筹的产出是机制与取舍，不是会议数量 |
| 失败形态 | 什么都在做、什么都差一点：没有取舍等于没有优先级 |

### 6.5 L4（资深／体系／系统）

**表 7　L4 能力要求**

| 项 | 内容 |
|---|---|
| 本级的台阶 | 从「自己交付」到「让组织能交付」——产出从项目变成机制。 |
| 能力档位 | 系统 |
| 责任半径 | 负责：组织的交付体系，包括质量门禁、资产化与能力培养，使结果不依赖个人。不负责：行业标准与生态 |
| 典型范围 | 跨项目群的体系设计（覆盖 10 个以上场景、多条业务线）；平台与工具链；对接分管领导与跨企业合作方；时间尺度半年到一年；体系级预算 |
| 能力档位要求 | 业务认知 系统；场景工程 系统；AI 技术与调试 系统；交付保障 系统；交付工程化 系统 |
| 证据要求 | a) 被执行过的 SOP 与质量门禁（有检查记录，不应仅为文档）；b) 资产库的复用数据（次数与工时下降）；c) 带出不少于 1 名能独立负责场景的下级，并有交接验收记录 |
| 交付产物 | 交付体系与门禁、资产库与复用指标、人才培养路径、跨项目复盘机制 |
| 量化口径 | 经营口径（资金占用、单位交付成本、资产入表、复用带来的毛利变化） |
| 晋升条件 | a) 体系落地不少于 2 个季度，且事故率／返工率可比较下降；b) 资产复用使同类项目工时下降不少于 30%；c) 培养出 L2 及以上人员不少于 1 名 |
| 破格条件 | 在行业层做出被外部采纳的方法论或标准，可直接进入 L5 评审（需外部采纳证据） |
| 常见越级误区 | 把「管的人多」当体系能力——体系看的是「人走了结果还在不在」 |
| 失败形态 | 制度漂亮但无人执行：门禁形同虚设，问题仍靠能人兜底 |

### 6.6 L5（专家／方法／行业）

**表 8　L5 能力要求**

| 项 | 内容 |
|---|---|
| 本级的台阶 | 从「组织内有效」到「外部也照做」——判定权交给外部证据。 |
| 能力档位 | 行业 |
| 责任半径 | 负责：方法被行业采用，包括标准、生态与跨企业迁移。影响对象不再是单个组织 |
| 典型范围 | 跨行业方法输出（含标准、教材、开源资产）；行业级方法论与平台生态；对接行业组织、生态伙伴、监管与标准机构；时间尺度一年以上 |
| 能力档位要求 | 业务认知 行业；场景工程 行业；AI 技术与调试 行业；交付保障 系统；交付工程化 行业 |
| 证据要求 | a) 被外部机构或同行采纳的方法论（引用、采用或联合发布记录）；b) 跨企业迁移成功案例不少于 2 家（非同一集团内）；c) 公开可查的标准、教材、开源资产或报告署名 |
| 交付产物 | 行业标准或方法论、生态合作机制、公开可引用的研究成果 |
| 量化口径 | 行业影响（被采纳次数、生态伙伴数、行业口径变化） |
| 晋升条件 | a) 方法被不少于 2 家非同集团企业实际采用并产生可核实结果；b) 在行业组织或标准工作中承担实质角色；c) 培养出 L3 及以上人员不少于 1 名 |
| 破格条件 | 本级以外部采纳为准，不接受自证；无外部证据不评定本级 |
| 常见越级误区 | 把「讲得多」当影响力——影响力看别人有没有照着做 |
| 失败形态 | 方法停留在演讲与文章：没有一家外部企业真正跑通 |

## 8 评价方法

### 8.1 评价方式

**8.1.1 自评**　由从业者本人依据本文件逐项判断，输出建议等级与缺口清单。自评结果仅用于定位，不得作为定级依据。

**8.1.2 证据评审**　由评审人依据提交材料判定等级。评审人应逐项记录「已核验」「待验证」「不满足」三种结论。

**8.1.3 复评**　按 8.4 规定的周期或触发条件重新评审。

### 8.2 证据审查规则

a) 每条能力要求至少有 1 件可核验材料支撑，否则记为「待验证」；

b) 材料应可被第三方独立核验（可复现的运行记录、可打开的文档、可查的外部采纳记录）；

c) 涉及客户信息的材料应脱敏，脱敏不影响可核验性；

d) 同一材料可用于支撑多个能力域，但不得用于支撑两个不同等级。

### 8.3 等级判定规则

**8.3.1 木桶判定**　等级取「五个能力域同时满足的最高等级」，不以加权平均替代。

**8.3.2 门槛判定**　能力域满足某等级，指其自评或评审结论达到该等级所要求的档位（见 6.2—6.6）。

**8.3.3 缺口计算**　未达到下一等级的能力域即为缺口，应按附录 B 补充对应证据。

**8.3.4 基线判定**　五个能力域未同时达到 L1 要求的，不评定等级，记为「未达基线」。

### 8.4 复评与时效

出现下列情形之一应重新评审：a) 更换岗位或业务场景；b) 跨行业迁移；c) 距上次评审满 24 个月。复评不自动继承原等级。

### 8.5 评价记录

评价记录应包含：受评人、评价日期、受评等级、各能力域结论、缺口清单、评审人签署。记录保存期不少于 3 年。

## 9 评价程序

**9.1 申请**　受评人提交自评表（附录 C）与证据材料清单（附录 B）。

**9.2 受理**　组织方核对材料完整性；材料不全的退回补正，补正期不超过 10 个工作日。

**9.3 材料审查**　评审人按 8.2 逐项审查，形成审查意见。

**9.4 评审**　不少于 2 名评审人独立判定；结论不一致时由第三人裁定。

**9.5 结论**　出具等级结论与缺口清单，注明有效期。

**9.6 复核与申诉**　受评人对结论有异议的，可在 15 个工作日内提出复核；复核由未参与原评审的人员执行，结论为最终结论。

## 附录 A（规范性）能力档位判定要点

A.1 判定一个能力域处于哪一档位时，应回答三个问题：这件事是否需要他人给出方法；是否处理过标准情形之外的异常；产出是否被别人照做。

A.2 判定要点见表 A.1。

**表 A.1　档位判定要点**

| 档位 | 判定问题 | 典型反例 |
|---|---|---|
| 依循 | 有模板或指引时能完成，且不需要自行判断 | 只做过一次、说不清步骤 |
| 独立 | 没有指引也能完成标准情形 | 换一个场景就不会 |
| 应变 | 处理过异常与非标准情形，并能说明取舍 | 只会按最佳实践套用 |
| 系统 | 做法被固化为机制，他人照做也成立 | 机制只在本人参与时运转 |
| 行业 | 被外部采纳，或参与外部标准工作 | 只有内部宣传，无外部引用 |

A.3 不得以「年限」「职级头衔」「证书数量」替代上述判定。

## 附录 C（资料性）自评问卷与计分说明

C.1 自评问卷按五个能力域各设置若干题目，每题按「没做过／做过但不稳定／稳定做到」三档计 0、1、2 分。

C.2 计分方法：先计算每个能力域的均分，再按 8.3 的门槛判定等级；等级取五域同时满足的最高等级。

C.3 参考门槛（0—2 分制）：依循 0.4、独立 0.9、应变 1.3、系统 1.6、行业 1.85。

C.4 自评结果应同时输出缺口清单与建议补充的证据卡，不得只输出等级。

C.5 在线自评工具见 https://fde.0706.tech/self-check/ 。
