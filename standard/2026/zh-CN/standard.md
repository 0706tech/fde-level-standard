## 第 0 章 结论摘要

### 0.1 三句话

1. **级别看责任半径，不看技术深度。** 一个人是不是 L3，取决于他「对什么负责」，而不是他会多少框架。
2. **五级双通道。** L1 初级 → L5 专家；技术交付（T）与业务交付（B）两条通道共用同一把尺子，只是能力权重不同。
3. **每级必须有证据。** 没有可观察材料，就不定级；「待验证」是一个合法结论，且比虚高的结论有用。

### 0.2 五级总表

| 级 | 中文职级 | 核心关键词 | 档位 | 责任对象 | 一句话定位 | 技术通道（T） | 业务通道（B） |
|---|---|---|---|---|---|---|---|
| L1 | 初级 | 执行 | 依循 | 任务 | 在框架内把一件事做对、交干净 | 初级交付工程师 | 初级业务分析 |
| L2 | 中级 | 独立 | 独立 | 场景 | 端到端对一个场景负责 | 交付工程师 | 场景交付顾问 |
| L3 | 高级 | 统筹 | 应变 | 项目群 | 统筹多场景组合，把攻坚变成打法 | 高级交付工程师 | 高级场景顾问 |
| L4 | 资深 | 体系 | 系统 | 组织体系 | 建交付体系，让结果不依赖个人 | 资深交付工程师 | 场景交付负责人 |
| L5 | 专家 | 方法 | 行业 | 行业方法 | 方法被行业采用 | 交付专家 | 场景专家 |

### 0.3 这份标准解决什么问题

| 谁在用 | 他真正想解决的问题 | 本体系给的答案 |
|---|---|---|
| 企业（用人方） | 「招个 FDE，给什么级别、什么钱、要什么证据」 | 五级 + 六件套 + 六张证据卡 + 薪酬区间 |
| 从业者 | 「我现在到底在哪一层，下一步补什么」 | 自测 + 缺口清单 + 晋级条件 |
| 服务商 | 「怎么向客户解释我的团队配置」 | 责任半径定义 + 可交付物清单 |
| 生态（园区/协会/院校） | 「培养出来的人对得上什么岗」 | 与岗位名一一对应的职级刻度 |

## 第 1 章 为什么这样命名

### 1.1 职级名与关键词分两层

**职级名用行业通用中文职级**：初级 / 中级 / 高级 / 资深 / 专家。理由很实际：

- 企业 HR 系统、JD、薪酬带宽表都是按这套词建的，用它能**直接挂上去**；
- 有大厂背景的人一眼能对到自己的位置，减少沟通成本；
- 反过来，如果自造词（如「交付协作者」「体系构建者」），实际使用中一定会被追问「相当于什么级别」，最后还是要翻译一遍。

**「执行 / 独立 / 统筹 / 体系 / 方法」是关键词，不是级别名**。它回答的是「这一级在负责什么」，用于解释与记忆：

> 「L3 是高级，关键词是统筹 —— 他不再是做好一个场景，而是让多个场景在一套机制里跑起来。」

这样命名有个副作用需要主动处理：**「专家」这个词容易被读成自夸**。因此凡出现 L5 的地方都要带一句限定：本表中的「专家」是职级名称（对应行业通用职级语境，如大厂 P8/P9 段位），不代表我们对自身水平的评价。

### 1.2 五个档位与五个级别一一对应

**这是整套标准最关键的结构约束**：能力档位不多不少，正好五档，与 L1–L5 一一对应。

| 档位 | 含义 | 对应级别 | 关键词 |
|---|---|---|---|
| 依循 | 有模板或指引时能完成，不需要自己判断 | L1 | 执行 |
| 独立 | 没有指引也能独立完成标准情形 | L2 | 独立 |
| 应变 | 能处理异常与非标准情形，并做出取舍 | L3 | 统筹 |
| 系统 | 能把做法固化为机制或标准，供他人照做 | L4 | 体系 |
| 行业 | 能影响外部：被同行采纳，或参与标准制定 | L5 | 方法 |

由此产生三条硬规则：

1. **不允许相邻两级同档**：如果 L2 与 L3 在某个域上同档，这个域就无法区分两级，定级会退化成凭整体印象；
2. **不允许跳档**：跳到下一档必须在同一域上补出该档要求的证据，不能「因为整体很强」而整体上调；
3. **每域每档都有具体描述**（见第 4 章的台阶矩阵）：档位名只是刻度，能判定的永远是描述里那件事做没做过。

## 第 2 章 设计原则

本标准只包含三件事：凭什么定这一级、拿什么证明、两条通道怎么共存。以下三条是全文的判定基础，后面的六级六件套都是它们的展开。

### 2.1 三条原则

| # | 原则 | 内容 | 为什么这样定 |
|---|---|---|---|
| 1 | **级别由责任半径决定** | 看「对什么负责」：任务 → 场景 → 项目群 → 组织体系 → 行业方法；并同时看失败后果与不可替代性 | 只看技能会得出「技术最强的人级别最高」的错误结论；只看年限则与真实能力脱钩（招聘市场上 90.1% 的 AI 岗位要求 8 年以上经验〔S7〕，说明年限早已不是有效刻度） |
| 2 | **证据优先于自述** | 每级都要求可提交材料：范围卡、失败样例集、运行手册、资产复用记录；没有材料就写「待验证」 | 自述无法核验且系统性偏高；「待验证」是合法结论，比虚高的结论有用 |
| 3 | **双通道共用一把尺子** | 技术交付（T）与业务交付（B）责任半径相同、薪酬区间相同，仅能力权重不同 | 单通道会系统性高估「能做出来」、低估「有人用」；而项目失败多发生在后者 |

### 2.2 本标准不包含什么（避免误解）

| 不是 | 说明 |
|---|---|
| 不是国家职业资格 | 《国家职业分类大典》中没有「前沿部署工程师」这一职业；本标准不做等级认定，也不发放证书 |
| 不是技术能力考试 | 不设笔试，不按题库打分；能力项只是观察维度，最终看材料与责任范围 |
| 不是薪酬承诺 | 薪酬区间是市场公开信息的估算，不代表任何雇主实际支付，也不作为我方报价依据 |
| 不是一次性评定 | 定级有时效：换岗、换场景、跨行业都应重新评审（见第 6 章） |

## 第 3 章 方法论：级别是怎么算出来的

### 3.1 一个核心判断：级别 = 责任半径

**责任半径**由三个要素决定，缺一不可：

1. **责任对象**（对什么负责）：任务 → 场景 → 项目群 → 组织体系 → 行业方法；
2. **失败后果**（做坏了谁承担）：自己返工 → 客户流程受影响 → 多部门目标受挫 → 组织能力受损 → 行业实践被误导；
3. **不可替代性**（换人成本）：换人 1 天 → 1 周 → 1 月 → 一季度 → 无法替换。

> 这三条一起看，就能解释一个常见困惑：**为什么「技术最强的人」不一定是最高级** —— 如果他的失败后果止于自己返工，责任半径就只有 L1–L2。

### 3.2 四个观察维度（打分用，不对外当分数用）

| 维度 | 低 | 高 | 观察方式 |
|---|---|---|---|
| **技能宽度** | 单一技术栈 | 跨技术 + 跨业务 + 跨组织 | 看他能独立处理几类问题 |
| **问题复杂度** | 有标准答案 | 无标准答案、需自己定义问题 | 看需求是否由他定义 |
| **影响范围** | 一个任务 | 一条业务线 / 一个生态 | 看他的产出被谁依赖 |
| **自主度** | 需人指导 | 自己定方向并对结果负责 | 看谁在为结果签字 |

**合成为级别的规则**：四维中「影响范围」与「自主度」具有决定性 —— 这两项不达标，前两项再高也只能停在 L2。这与大厂职级的实际判定逻辑一致：**级别先看 scope，再看技能**。

### 3.3 双通道的能力权重

| 域 | 技术通道权重 | 业务通道权重 | 说明 |
|---|---|---|---|
| 业务认知 | 3 | 5 | 业务通道必须能用客户指标语言说话 |
| 场景工程 | 3 | 5 | 同上，场景定义是业务通道的主战场 |
| AI 技术与调试 | 5 | 2 | 技术通道要能自己定位模型与检索问题 |
| 交付保障 | 3 | 4 | 数据权限、成本、干系人，两条通道都要 |
| 交付工程化 | 5 | 3 | 资产化对技术通道是硬指标，对业务通道是要求 |

> 权重不是评分公式，是**判定时的注意力分配**：同一份证据，两条通道看的重点不同。

## 第 4 章 五级标准全文

> 每级给六件套（责任半径 / 典型 scope / 能力要求 / 可观察证据 / 交付产物 / 量化口径）+ 晋级条件 / 破格规则 / 常见越级误区 / 失败形态。
> 能力标记：`基础` 能在指导下完成；`熟练` 能独立完成；`精通` 能处理异常与取舍；`贯通` 能定义标准并教会别人。

### 4.1 L1 · 初级 · 执行（对任务负责）

| 项 | 内容 |
|---|---|
| **本级的台阶** | 入门基线：从「会用工具」变成「能交干净一件事」。 |
| **能力档位** | 依循（五档之一，对应本级的整体刻度） |
| **责任半径** | 负责：一件边界清晰的任务按时按质交付。不负责：场景范围与验收的定义、预算、客户关系 |
| **典型 scope** | 1 个场景中的单个任务；1 个系统内 1–2 个模块；对接一线使用者与导师；时间尺度天到周；不承担预算决策 |
| **能力要求** | 业务认知 基础 / 场景工程 基础 / AI 技术 基础 / 交付保障 基础 / 交付工程化 基础 |
| **可观察证据** | ① 能独立跑通既有模板并说明每步在做什么；② 有失败样例与修复记录（不是只贴成功截图）；③ 交接时能说清「哪里最容易出错」 |
| **交付产物** | 可运行的模块或配置、启动说明、失败样例记录 |
| **量化口径** | 任务级耗时与返工次数（分钟/小时口径） |
| **晋级条件** | 连续 3 个任务无需返工；能自己判断「该不该暂停并求助」；至少 1 份文档被他人直接复用 |
| **破格规则** | 不做破格。本级价值在基本功，跳过等于把风险留给下一级 |
| **常见越级误区** | 把「用过很多工具」当成能力 —— 工具熟练度不等于交付能力 |
| **失败形态** | 任务做完但交不干净：没文档、没失败样例，第二个人接手要从头问 |

### 4.2 L2 · 中级 · 独立（对场景负责）

| 项 | 内容 |
|---|---|
| **本级的台阶** | 从「交任务」到「对结果负责」—— 开始为一条流程的成败签字。 |
| **能力档位** | 独立（五档之一，对应本级的整体刻度） |
| **责任半径** | 负责：一个场景从需求确认到上线后运行的全环。不负责：多场景优先级、组织机制、跨部门资源调配 |
| **典型 scope** | 1 个场景全环；1–3 个系统的数据与接口打通；对接业务负责人 + 一线骨干 + IT/数据；时间尺度周到月；单场景量级预算（需报批） |
| **能力要求** | 业务认知 熟练 / 场景工程 熟练 / AI 技术 熟练 / 交付保障 熟练 / 交付工程化 基础 |
| **可观察证据** | ① 范围卡（场景边界、基线数字、验收动作）；② ≥20 条失败样例集，能说清它什么时候会错；③ 一次真实流程跑通记录（谁在什么时间用了什么） |
| **交付产物** | 可运行场景、验收单、失败样例集、运行手册初版 |
| **量化口径** | 场景指标（准确率、处理周期、单次耗时、错误率） |
| **晋级条件** | 独立完成 ≥2 个场景且有 1 个连续运行 4 周以上；能自己定义基线并把验收写成可判断条件；交付物中 ≥1 件被第二个场景复用 |
| **破格规则** | 有同等规模场景的完整交付证据（含验收与接管）可跨过任务级考察，但不免除证据评审 |
| **常见越级误区** | 把「系统上线」当交付完成 —— 上线只是开始 |
| **失败形态** | 场景做完但没人用：验收写的是功能，不是业务变化 |

### 4.3 L3 · 高级 · 统筹（对项目群负责）

| 项 | 内容 |
|---|---|
| **本级的台阶** | 从「做好一个」到「决定做哪几个」—— 第一次拥有取舍权。 |
| **能力档位** | 应变（五档之一，对应本级的整体刻度） |
| **责任半径** | 负责：一组场景的组合、优先级与资源，以及让攻坚可重复的机制。不负责：组织级标准与人才培养体系 |
| **典型 scope** | 3–10 个场景的组合（含取舍）；跨系统跨部门编排；对接部门负责人及以上与多方供应商；时间尺度季度；参与预算编制 |
| **能力要求** | 业务认知 熟练 / 场景工程 精通 / AI 技术 精通 / 交付保障 精通 / 交付工程化 熟练 |
| **可观察证据** | ① 场景组合规划（为什么先做这 3 个、放弃那 5 个）；② 可重复的评审与运营机制（谁在什么节点检查什么）；③ 至少 1 次跨部门冲突的处理记录（含取舍理由） |
| **交付产物** | 组合路线图、评审与运营机制、架构决策记录、可复用资产 ≥2 件 |
| **量化口径** | 组合价值（总成本、总工时、合格率、复用率） |
| **晋级条件** | 同时统筹 ≥3 个场景且全部达验收；建立被他人沿用 ≥2 次的机制或资产；资源不足时能做可解释的取舍 |
| **破格规则** | 在单一复杂系统上达成 L4 级资产化成果（跨项目复用 ≥3 次）可破格，需评审一致通过 |
| **常见越级误区** | 把「协调会议多」当统筹能力 —— 统筹的产出是机制与取舍，不是会议数量 |
| **失败形态** | 什么都在做、什么都差一点：没有取舍等于没有优先级 |

### 4.4 L4 · 资深 · 体系（对组织体系负责）

| 项 | 内容 |
|---|---|
| **本级的台阶** | 从「自己交付」到「让组织能交付」—— 产出从项目变成机制。 |
| **能力档位** | 系统（五档之一，对应本级的整体刻度） |
| **责任半径** | 负责：组织的交付体系 —— 质量门禁、资产化、能力培养，让结果不依赖个人。不负责：行业标准与生态 |
| **典型 scope** | 跨项目群的体系设计（覆盖 10+ 场景 / 多业务线）；平台与工具链；对接分管领导与跨企业合作方；时间尺度半年到一年；体系级预算 |
| **能力要求** | 五域全部 精通（业务认知、场景工程、AI 技术、交付保障、交付工程化） |
| **可观察证据** | ① 被执行过的 SOP 与质量门禁（有检查记录，不是文档摆设）；② 资产库的复用数据（次数与工时下降）；③ 带出 ≥1 名能独立负责场景的下级，并有交接验收记录 |
| **交付产物** | 交付体系与门禁、资产库与复用指标、人才培养路径、跨项目复盘机制 |
| **量化口径** | 经营口径（资金占用、单位交付成本、资产入表、复用带来的毛利变化） |
| **晋级条件** | 体系落地 ≥2 个季度且事故率/返工率可比较下降；资产复用使同类项目工时下降 ≥30%；培养出 L2+ ≥1 名 |
| **破格规则** | 在行业层做出被外部采纳的方法论或标准，可直接进入 L5 评审（需外部采纳证据） |
| **常见越级误区** | 把「管的人多」当体系能力 —— 体系看的是「人走了结果还在不在」 |
| **失败形态** | 制度漂亮但没人执行：门禁形同虚设，问题仍靠能人兜 |

### 4.5 L5 · 专家 · 方法（对行业方法负责）

| 项 | 内容 |
|---|---|
| **本级的台阶** | 从「组织内有效」到「外部也照做」—— 判定权交给外部证据。 |
| **能力档位** | 行业（五档之一，对应本级的整体刻度） |
| **责任半径** | 负责：方法被行业采用 —— 标准、生态、跨企业迁移。影响的不再是单个组织 |
| **典型 scope** | 跨行业方法输出（含标准、教材、开源资产）；行业级方法论与平台生态；对接行业组织、生态伙伴、监管与标准机构；时间尺度一年以上 |
| **能力要求** | 四域 贯通（业务认知、场景工程、AI 技术、交付工程化），交付保障 精通 |
| **可观察证据** | ① 被外部机构或同行采纳的方法论（引用、采用或联合发布记录）；② 跨企业迁移成功案例 ≥2 家（非同一集团内）；③ 公开可查的标准、教材、开源资产或报告署名 |
| **交付产物** | 行业标准或方法论、生态合作机制、公开可引用的研究成果 |
| **量化口径** | 行业影响（被采纳次数、生态伙伴数、行业口径变化） |
| **晋级条件** | 方法被 ≥2 家非同集团企业实际采用并产生可核实结果；在行业组织/标准工作中承担实质角色；培养出 L3+ ≥1 名 |
| **破格规则** | 本级以外部采纳为准，不接受自证；无外部证据不评定本级 |
| **常见越级误区** | 把「讲得多」当影响力 —— 影响力看别人有没有照着做 |
| **失败形态** | 方法停留在演讲与文章：没有一家外部企业真正跑通 |

### 4.6 台阶矩阵：五个域 × 五个级别

> 这张表是「一个职级一个台阶」的落点。读法：横向看一个域的进阶，纵向看一个级别的全貌。
> 同一列里不应出现「和上一列差不多」的描述 —— 若出现，说明该级在这个域上没有实质进步。

| 能力域 | L1 依循 | L2 独立 | L3 应变 | L4 系统 | L5 行业 |
|---|---|---|---|---|---|
| **业务认知** | 按现成提纲记录流程与角色，复述不出错 | 独立跑完流程梳理，说清环节的输入输出与责任人 | 识别口径冲突与伪需求，在多部门诉求间判断真痛点 | 判断业务线的 AI 适用边界，写成可复用的评估清单 | 提出被同行采用的行业问题框架或分类方法 |
| **场景工程** | 按模板填范围与验收，不擅自扩大 | 独立确认范围、量出基线、写出可判断的验收动作 | 对一组场景排优先级并取舍，说明放弃理由 | 定义组织的场景准入与验收标准，并让评审照此执行 | 输出被外部引用的场景分类与判定方法 |
| **AI 技术与调试** | 按脚本复现正常与失败输出并记录现象 | 建 ≥20 条失败样例集，区分检索与生成问题 | 处理模型/数据/工具交互的复杂故障并设计兜底 | 建评估与回归机制，把质量做成可检查的门禁 | 提出被外部采用的评估方法或质量指标 |
| **交付保障** | 按清单同步进展、完成交接，不遗漏风险 | 打通数据与权限，说明脱敏与最小必要，推进接管 | 协调多方依赖与变更，控制范围蔓延与成本超支 | 建立数据治理、事故应对与交付质量机制 | 参与行业交付与合规规范的制定或实质讨论 |
| **交付工程化** | 整理可复用片段与说明供他人取用 | 产出 ≥1 件资产并被第二处使用 | 设计复用接口，沉淀 ≥2 件并统计复用效果 | 建资产库与复用指标，让同类项目工时可见下降 | 资产被外部企业采用或开源复用 |

### 4.7 六个级别的「失败形态」对照（用于快速自查）

| 级 | 典型失败 | 一句话诊断 |
|---|---|---|
| L1 | 交不干净 | 活干完了，别人接不住 |
| L2 | 无人使用 | 系统上线了，流程没变 |
| L3 | 什么都做 | 没有取舍，等于没有优先级 |
| L4 | 制度空转 | 门禁在纸上，问题靠能人 |
| L5 | 只讲不做 | 没有外部企业真正跑通 |

## 第 5 章 双通道与转轨

### 5.1 两条通道不是两条赛道

两条通道**共用同一把刻度尺**（责任半径），但能力权重不同：

- **技术通道（T）**：以系统构建、数据接入、评估调试为主线，对「能不能跑通、跑稳」负责。典型产出是连接器、评估集、架构决策记录。
- **业务通道（B）**：以行业认知、场景定义、价值证明为主线，对「该不该做、做成没做成」负责。典型产出是场景组合、验收设计、价值核算。

**同级等价**：L3-T 与 L3-B 在责任半径上完全相同，薪酬区间也相同。区别只在「证据的形状」：T 的证据偏系统与评测，B 的证据偏场景与指标。

### 5.2 转轨规则

| 情况 | 规则 |
|---|---|
| 同级转轨（L3-T → L3-B） | 允许，需补交目标通道的 2 张核心证据卡（B 通道补场景与验收卡 + 业务诊断卡；T 通道补 AI 调试与评估卡 + 数据与权限卡） |
| 跨级转轨 | 需按目标级重新评审，不因原级高而自动通过 |
| 转轨后定级 | 不得高于原级（避免「转轨升职」的套利） |
| 双通道都合格 | 不设「双通道叠加」特权；评定时选主通道，另一通道作为加分证据 |

### 5.3 为什么必须有业务通道

因为大量 FDE 项目的失败原因不是技术，而是**场景选错或价值没被证明**。如果一个组织里所有能定级的人都是技术背景，这个组织会系统性地高估「能做出来」，低估「有人用」。

## 第 6 章 评价方法

### 6.1 三种评价方式，三种用途

| 方式 | 谁做 | 用途 | 局限 |
|---|---|---|---|
| **自评** | 本人 | 定位与找缺口 | 会高估，尤其 L3 以上 |
| **证据评审** | 2 名以上同級或上级（含 1 名业务侧） | 定级、招聘、晋升 | 成本高，需材料齐备 |
| **30/60/90 复评** | 直接负责人 | 新人入职与项目结项 | 只看短期，不看体系贡献 |

### 6.2 证据评审的最小材料集

| 材料 | 对应证据卡 | 不合格的样子 |
|---|---|---|
| 范围卡（范围、基线、验收动作） | 场景与验收卡 | 只写功能清单 |
| 失败样例集（≥20 条） | AI 调试与评估卡 | 全是成功案例 |
| 数据与权限说明 | 数据与权限卡 | 只写「已打通」 |
| 运行手册 | 交付运营卡 | 没有异常处理章节 |
| 资产清单与复用记录 | 资产化卡 | 只有一次使用记录 |
| 业务指标前后对比 | 业务诊断卡 | 只有截图没有数字 |

### 6.3 复评节奏

| 节点 | 看什么 | 不合格怎么处理 |
|---|---|---|
| 第 30 天 | 能否启动、是否有范围卡 | 补材料，不降级 |
| 第 60 天 | 是否知道「它什么时候会错」 | 补失败样例集 |
| 第 90 天 | 换人能否跑通 | **不能换人就不得定级为 L2 及以上** |

## 第 7 章 与外部体系的关系（对齐但不依赖）

### 7.1 国家层面：没有 FDE 这个职业

- 《国家职业分类大典》中无「前沿部署工程师」；相关的是人工智能训练师、生成式人工智能系统应用员等新职业，有人社部体系的职业技能等级认定。
- 实证：上海 2025 年累计 1.63 万人次参加人工智能训练师评价、1.09 万人取得职业技能等级证书〔S8〕。
- **结论**：FDE 目前只能参考国家新职业体系的方法（等级 + 认定 + 复核），**不能自称国家职业资格**。

### 7.2 行业层面：已有可对齐的分级

已有一份较完整的行业分级（AI-FDE 联合工场 & 大任智库，2026-08），其核心是「责任半径 + 四域能力 + 素养双路径 + 晋级规则」。本文与其**口径同源**，差异在：增设 L5、分双通道、把「交付工程化」独立成域。引用时标注出处，不复制其表格。

### 7.3 我们的取舍

| 取其长 | 不取之处 |
|---|---|
| 责任半径作为级别内核 | 不采用「素养四力」单独成体系（对本方使用场景过重） |
| 分级量化口径（越高级越接近经营语言） | 不把测评分数作为唯一门槛（分数可刷，证据不可） |
| 晋级 + 破格规则 | 不做认证与发证（见第 8 章免责） |

## 第 8 章 大厂职级参考与市场薪酬

### 8.1 大厂职级参考区间

> **公开信息整理 · 非官方口径 · 各公司职级近年多次改革**。本表只给区间，不给点值，并标注置信度。

| 本文级别 | 阿里 | 字节 | 腾讯 | 百度 | 置信度 |
|---|---|---|---|---|---|
| L1 初级 | P4–P5 | 1-1 ~ 2-1 | T1.3–T2.1 | T4–T5 | 中 |
| L2 中级 | P5–P6 | 2-1 ~ 2-2 | T2.1–T2.3 | T5–T6 | 高 |
| L3 高级 | P6–P7 | 2-2 ~ 3-1 | T2.3–T3.1 | T6–T7 | 中 |
| L4 资深 | P7–P8 | 3-1 ~ 3-2 | T3.1–T3.3 | T7–T8 | 中 |
| L5 专家 | P8–P9 | 3-2 ~ 4-1 | T3.3–T4 | T8–T9 | 低 |

**为什么只给区间、不给精确对应**

1. 大厂职级**没有官方公开表**，流传的版本均为第三方整理，且各家近年都调整过（阿里弱化 P 序列对外表述、腾讯专业族体系调整、字节用 1-1~5-2、百度 T/P 双序列）；
2. 精确对应一旦公开，会立刻被当成**招聘承诺与薪资谈判依据**，而它承载不了这个功能；
3. 区间已经足够解决真实问题（判断「该找什么级别的人」「我的当前位置」），再精确就只剩风险。

### 8.2 市场薪酬区间

> **口径**：招聘广告月薪 × 12–15 个月反推，并用薪酬报告中位数交叉校准；**不是分位值，也不是任何雇主的实际支付**。
> **单位**：年薪（万元，税前，含奖金不含股权）。**时间**：2026 年 10 月。

| 级别 | 苏州 | 杭州 | 上海 | 北京/深圳 | 校准依据 |
|---|---|---|---|---|---|
| L1 | 12–20 | 14–23 | 16–26 | 18–30 | 招聘广告月薪 1.2–2.0 万〔S2〕 |
| L2 | 20–33 | 23–38 | 26–42 | 30–48 | AI 应用集成月薪均值 4.7 万的下沿〔S1〕 |
| L3 | 32–52 | 36–59 | 42–68 | 48–78 | 含场景负责人溢价（AI 技能溢价 +62%）〔S5〕 |
| L4 | 50–85 | 56–95 | 65–110 | 75–130 | 对齐资深架构师区间下段〔S4〕 |
| L5 | 80–130 | 90–145 | 100–170 | 120–200 | 参照头部资深 150–200 万的下沿〔S4〕，样本极少 |

> **杭州口径**：无单独的城市分档公开数据，按长三角区间（介于苏州与上海之间）估算；其余城市依据同一批招聘广告与薪酬报告口径。

**三条使用纪律**

1. 行业差异显著：制造行业 AI 技能溢价 +73%，消费品 +118%，政府仅 +16%〔S5〕——同级别在不同行业不该用同一个数；
2. 不得把本表当报价依据：我方服务报价按场景与工作量核算，与候选人薪酬无直接换算；
3. 不得跨来源拼接：不同机构的样本口径不同，混用会得出错误结论；
4. 城市差异不是「同岗不同酬」的证据：一线城市高出的部分通常由业务复杂度与成本结构共同决定，不能直接作为谈薪依据。

## 第 9 章 免责与使用边界

1. **不是国家职业资格**：本体系为能力分级参考，我们不发放证书、不举办考试；《国家职业分类大典》中没有「前沿部署工程师」。
2. **不是认证机构**：任何以「FDE 认证」名义收费的机构都与本体系无关。
3. **大厂与薪酬为公开信息整理**：不官方、会变化、不代表任何雇主实际支付，不作为我方报价或承诺依据。
4. **自评不等于评定**：自测结果是自我定位参考，不构成对外能力背书。
5. **引用规则**：可引用本表与定义，须注明「零七零六科技《FDE 职级体系（2026 版）》+ 章节」；不得改写后作为自有标准发布，不得用于商业培训而不取得许可。

## 附录 A 术语表

| 术语 | 定义 |
|---|---|
| 责任半径 | 责任对象 × 失败后果 × 不可替代性三者合成的级别判据 |
| 档位 | 依循 / 独立 / 应变 / 系统 / 行业五档，与 L1–L5 一一对应，每域每级各占一档 |
| 台阶 | 某一级相对上一级的实质变化（写在每级表格第一行），必须是具体的一件事，不是形容词 |
| 场景（scene） | 一个有边界、可度量、可验收的业务动作，不是「一个系统」或「一个部门」 |
| 证据卡 | 六类可提交材料，用于证明某级能力（业务诊断 / 场景与验收 / 数据与权限 / AI 调试与评估 / 交付运营 / 资产化） |
| 资产（asset） | 连接器、模板、评估集三者之一；判据是「第二次交付确实用上了」 |
| 双通道 | 技术交付（T）与业务交付（B），共用责任刻度、权重不同 |
| 破格 | 跨过常规晋级条件，但需评审一致通过且有可核实的外部证据 |

## 附录 B 证据材料清单（提交评审时的最小集）

1. 范围卡（含基线、验收动作、责任人）
2. 失败样例集（≥20 条，覆盖正常/边界/冲突/无答案）
3. 数据与权限说明（含脱敏与最小必要）
4. 运行手册（含异常处理与回滚）
5. 资产清单与复用记录
6. 业务指标前后对比（含取数口径与时间窗）
7. 交接验收记录（换人跑通）

## 附录 C 本体系不使用的数据

1. 来源不明的「FDE 平均薪资」——查不到样本与口径的一律不用；
2. 任何单一雇主的薪酬爆料（脉脉/看准等社区帖）——无法核实的不用；
3. 把「某厂职级」写成精确等号的说法 —— 无官方来源，不用；
4. 培训机构宣传的「就业薪资涨幅」——与本体系无因果关系，不用。
